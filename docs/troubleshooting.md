# 故障排查

本文档列出使用 dsh-typst 时的常见问题、可能原因与对应处理方式。

## 1. 面板停在安装引导页

- **现象**：打开 Typst 面板只看到安装引导，看不到预览。
- **原因**：插件在本机找不到 typst，或找到的版本低于 0.12.0。查找范围是 PATH、常见安装位置与登录 shell。
- **排查**：按引导页列出的命令安装 typst；装好后插件每几秒自动重查一次，无需重启。装在查找范围之外时，在插件设置 **Typst 路径** 里填完整路径。

## 2. 提示 Typst 版本过旧

- **现象**：面板显示 `too_old`，工具返回 `TYPST_TOO_OLD`。
- **原因**：找到的 typst 低于 0.12.0（插件支持的最低版本）。
- **排查**：用装它的那个工具升级（Homebrew 用 `brew upgrade typst`，cargo 用 `cargo install --locked typst-cli`），或在插件设置 **Typst 路径** 指向另一个安装。

## 3. Typst 存在但跑不起来

- **现象**：面板显示 `error`，工具返回 `TYPST_UNUSABLE`。
- **原因**：可执行文件找到了，但 `--version` 失败——通常是损坏的安装、缺少执行权限，或架构不匹配。
- **排查**：在终端里直接跑 `typst --version` 看报什么；能修的安装就重装，架构不对就换一个匹配本机的构建。

## 4. 找不到主文件

- **现象**：工具返回 `TYPST_NO_MAIN`，面板的预览是空的。
- **原因**：工作区里没有 `.typ` 文件，或有多个候选而插件无法判断哪个是主文件。
- **排查**：确认工作区里确有 `.typ` 文件；多个候选时用 `typst_set_main` 指定你本该传给 `typst compile` 的那一个，或在面板工具栏里切换。

## 5. 预览一直是空的

- **现象**：工具返回 `TYPST_NO_PREVIEW`。
- **原因**：还没有一次成功的编译——文档有编译错误，或主文件还没选好。
- **排查**：先 `typst_status` 看 `phase` 与错误数；有错误就 `typst_check` 读诊断并修掉。

## 6. `typst_check` 一直等着不返回

- **现象**：工具在默认 60 秒后失败，返回 `TYPST_TIMEOUT`。
- **原因**：磁盘上的改动始终没有编译完——最常见的是 watch 进程没有察觉这次保存。
- **排查**：确认文件确实写到了磁盘（有些编辑器先写临时文件再改名）；`typst_check` 会在这种情况下重启 watch，重试一次通常就好。也可以在面板里用工具栏的重启按钮。

## 7. watch 进程退出

- **现象**：工具返回 `TYPST_WATCH_FAILED`，面板不再更新。
- **原因**：`typst watch` 自身崩溃或被系统杀掉。
- **排查**：在宿主日志里找 `[dsh-typst]` 前缀的行看崩溃前的最后一条；重启会话或切换主文件会重建 watch。

## 8. 高亮没有落到预期位置

- **现象**：Agent 高亮出现，但位置不对或变成了灰色（stale）。
- **原因**：高亮靠引文在渲染文本里定位。对数学、编号、目录、参考文献和函数生成的文本，引文往往不按原样出现在渲染结果里。
- **排查**：让 Agent 改用 `file` + `line` 指向源码行，而不是引文；源码行的定位不受渲染文本的近似性影响。

## 9. 引文高亮找不到

- **现象**：工具返回 `TYPST_QUOTE_NOT_FOUND`。
- **原因**：引文按渲染后的原样抄写才对；把标记语言（`#`、`` ` `` 等）一起抄了进去，或抄的是源码而非渲染结果。
- **排查**：从预览里直接复制那几个字，去掉标记语言后重试。

## 10. 导出路径被拒绝

- **现象**：工具返回 `TYPST_PATH_OUTSIDE_WORKSPACE`。
- **原因**：路径解析后落在工作区之外，例如 `../outside.pdf` 或指向工作区外的绝对路径。
- **排查**：改成工作区相对路径（如 `out/paper.pdf`）。插件只往工作区内写，导出不了工作区外的地方。

## 11. 导出时编译失败

- **现象**：工具失败，错误名为 `TYPST_COMPILE_FAILED`，消息里带着完整诊断。
- **原因**：文档有编译错误，导出走的是一次真实的编译。
- **排查**：按诊断里的位置修掉错误后重试。预览能显示不等于文档能编译——预览保留的是上一次成功的版本。

## 12. 面板不随保存更新

- **现象**：改了文件，预览没有重新编译。
- **原因**：watch 没有察觉这次改动，或改动还没落盘。
- **排查**：确认编辑器已经写盘（不是只改了内存里的缓冲区）；在面板工具栏里手动重启一次 watch。改动落盘后仍不更新时，看宿主日志里 `[dsh-typst]` 的行。

## 13. 选中的文字没有匹配到源码

- **现象**：面板送出的消息里没有源码位置，只有选中的文字。
- **原因**：文本匹配没找到候选——选中的内容来自生成的文本（目录、编号、参考文献），或者该文件超过了匹配的大小上限。
- **排查**：选中正文散文再试一次；需要精确位置时直接让 Agent 用 `typst_show` 的 `file` + `line` 形式。

## 14. 预览页面空白

- **现象**：面板里看不到页面内容。
- **原因**：PDF 还没有成功编译出来，或上一份快照已被丢弃（插件只保留最近 3 份快照用于高亮重定位）。
- **排查**：看工具栏的阶段指示；如果是 `error`，问题在编译而不是显示。

## 15. 改了设置却没生效

- **现象**：填了新的 **Typst 路径**，插件仍用旧的 typst。
- **原因**：路径没保存，或者该工作区的会话还没重建。
- **排查**：重新打开设置确认值已保存。设置是 volatile 的：提交后所有活跃会话会重新定位一次可执行文件，watch 随之重启，通常几秒内生效。

## 16. 找不到 Typst 面板

- **现象**：右侧栏里没有 Typst 选项。
- **原因**：插件未启用，或宿主界面没有右侧停靠栏。
- **排查**：在插件管理器里确认 **dsh-typst** 已启用；界面需要是带右侧停靠栏的 Web 界面版本。也可以从引导页进入面板。
